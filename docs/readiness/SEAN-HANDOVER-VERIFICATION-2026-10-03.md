## 2. Owner account — activation order and revocation

Specialist lane A (identity/MFA), read against HEAD; line numbers as at commit `2fc508d`.

**What was true at the start.** `mustChangePassword` was enforced by `app/dashboard/layout.tsx` only; `lib/api-authz.ts` and `proxy.ts` never read it, so a session on a temporary password could call every protected `/api/*` route. For the owner, production was still covered by the not-yet-enrolled-authenticator gate (`api-authz.ts:116`, `proxy.ts:269`); the real exposure was a coach handed a temporary password, or an enrolled manager/owner after an operator reset once past the TOTP challenge. `set-password` cleared the flag but bumped no `sessionVersion`, so a second device still on the temporary password stayed signed in.

**Fixed (local, unpushed).**
- `6457180` — set-password bumps `sessionVersion`; the device that changed the password is re-issued its token at the new version, every other device is signed out on its next request.
- `2fc508d` — `mustChangePassword` is a token claim (minted at credentials and Google sign-in, stamped onto pre-existing tokens from one DB read, preserved across impersonation). `proxy.ts:287` refuses it before the authenticator gate: pages → `/set-password`, `/api/*` → JSON 403; `requireApiRole` refuses with the same `{ ok:false, error }` shape as the MFA refusal. `/set-password`, `/login/totp/setup` and `/api/auth/*` stay reachable. Order is therefore enforced end to end: **temporary password → own password → authenticator → club data**, pages and API alike.
- Tests: `api-authz-password-gate`, `proxy-activation-gates`, `owner-activation-order` (scans `app/` to pin that every write turning the flag on also bumps the version), `set-password-route` extended. 10 files / 126 tests pass; each new file goes red when its source file is reverted (3 / 3 / 10 / 4 failures).

**Revocation is immediate, not windowed.** `checkSessionVersion` runs on every Node-runtime JWT pass (`auth.ts:1016-1036`); `proxy.ts` declares no edge runtime and Next 16 Proxy runs on Node, so the check runs there too. A `sessionVersion` bump signs a browser out on its next request. Fail-open on a database error (verdict `unknown`, reported to Sentry) — stated as a limit.
