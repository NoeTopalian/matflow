**States.** *Composed*: template rendered in memory (`lib/email.ts:363-365`), no row. *Queued*: row written before the provider call (`lib/email.ts:416`). *Provider-accepted*: `sent` with `resendId` once Resend returns without error (`lib/email.ts:463-467`). *Delivered*: only when Resend's `email.delivered` webhook lands (`app/api/webhooks/resend/route.ts:84-86`). Terminal failure states are `failed`, `bounced`, `complained` (`route.ts:31-39`). Nothing sweeps rows stuck at `queued` (no reader of `"queued"` outside `lib/email.ts`).

**Success before durable completion.** `sent` means Resend accepted the message, not that it arrived (`lib/email.ts:463-467`). If the process dies between the Resend call and the `sent` update, the mail may have gone while the row stays `queued` with no `resendId`; any later webhook for it is then acked as "email not found" and dropped (`app/api/webhooks/resend/route.ts:127-131`). The same race applies when Resend's `email.sent`/`email.delivered` webhook arrives before `lib/email.ts:463-467` has stored `resendId`. Webhook DB failures are acked 200 and lost (`route.ts:150-153`).
