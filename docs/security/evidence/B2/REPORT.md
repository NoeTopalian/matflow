## Root cause (01-root-cause-and-policy-matrix.md)
All 47 tenant_isolation policies have one shape: current_setting('app.bypass_rls')='on' OR the row's tenant matches current_setting('app.current_tenant_id') (37 compare tenantId, 1 Tenant.id, 9 child tables via parent). Both are custom session settings Postgres never registered — any role sets them freely; the bypass is a setting the runtime role switches on for itself. Ruled out: SET ROLE to owner refused (42501); no table ownership / BYPASSRLS on the runtime role; no SECURITY DEFINER functions in public; row_security=off raises 42501. FORCE RLS does nothing against the owner (BYPASSRLS). Measured as matflow_app on TEST (read-only, rolled back, counts): bypass on → 141 clubs and the audit log of 132 clubs visible; forged tenant id → 894 members of one club; the runtime role may UPDATE Operator.passwordHash, _prisma_migrations and PlatformConfig (proven with no-row-matching updates).

## Correction to campaign conclusion 3
Ordinary requests through withTenantContext: all 47 policies hold (no context → nothing visible; other-club rows invisible, updates/deletes match 0, inserting/moving into another club refused; context gone after commit, after error+rollback, after a rolled-back savepoint; concurrent pooled transactions separate). Anyone running their own SQL as the runtime role (leaked URL, injection, compromised dependency): all 47 FAIL — one set_config opens every club read/write; a forged id opens any club; a session-level setting left on a connection leaks into later transactions. Non-RLS tables fully writable by the runtime role. Under the owner login RLS never applies. Iteration-1 both-role counts did not show this because the bypass was used only to build fixtures, never as an attacker.

## Code fix (red first, both roles)
lib/prisma-tenant.ts withTenantContext now turns app.bypass_rls OFF for its own transaction in the same statement that sets the tenant — before, a session-level bypass left on a reused connection let club A's transaction see club B. Proof: with the reset removed sec-b2-stale-bypass-db fails exactly the intended cell (1/6) on the same backend process; with it 6/6 each role. Optional signed context (RLS_CONTEXT_SIGNING_KEY) coded but inert under today's policies; app signature matches the database recomputation (sec-b2-signed-context-db 1/1 each role). Unit sec-b2-tenant-context 9 (statement shape, signature maths, malformed key fails before a transaction opens, source scan: no session-level app.* setting in app/, lib/, auth.ts, proxy.ts — planted example caught); removing the fix fails 1. Script guard hardened: substring host checks in create-restricted-role.ts and apply-rls-enforcement.ts replaced by scripts/readiness/rls-test-target.mjs (12/12): resolves the host as pg does, requires the exact TEST endpoint, refuses host=/hostaddr=/options=/endpoint= overrides, case tricks and inherited PG* env, passes the driver an explicit config. create-restricted-role.ts also revokes the runtime role's rights on _prisma_migrations (script not re-run).

## Recommended design P2 (02-boundary-design.md; harness-run-2026-10-09.json)
System role, not a setting: cross-club access only for matflow_system (cannot log in, no BYPASSRLS); operator and cron work logs in as a separate matflow_ops account with its own URL; the runtime role is never a member. Signed tenant context: the database accepts a tenant id only with a signature over tenant, backend process and transaction start time, checked by matflow_sec.ctx_tenant() (SECURITY DEFINER owned by matflow_system, fixed search_path, qualified names, EXECUTE granted by name never PUBLIC, key material readable only by the system role); a captured signature is useless in any other transaction or connection. Narrow lookups tenant_id_by_* (slug, kiosk token, Stripe account…) return one tenant id. Append-only audit at the runtime boundary. Rejected: wrapping the bypass in a function (same bypass behind a door); letting the runtime role switch into a privileged role; role-keyed unsigned context P1 (forgeable); pg_locks/txid binding (cost per query). Harness, 16 attack checks as the real roles: current design fails 6 (bypass, forged tenant, replayed signature, session leftovers, audit rewrite, provenance rewrite); P1 fails 4; P2 fails NONE (incl. legitimate-access checks); P2 with the bypass clause restored fails 3 (regression caught). Clean-up count-checked.
