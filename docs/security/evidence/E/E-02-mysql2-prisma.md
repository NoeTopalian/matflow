# E-02 The mysql2 and prisma advisories (reconciles AH-09 "not applicable")

Lane E, 9 Oct 2026, candidate 2a6487e (lockfile blob ddf84f4, the same as c837e38).

|---|---|---|---|
| mysql2 **3.15.3** (`node_modules/mysql2`, pinned exactly by prisma 7.10.0) | GHSA-3f6p-5ww8-9rcr: the auth plugin can be downgraded to `mysql_clear_password`, which leaks plaintext credentials | high | introduced 0, **fixed 3.22.0** |

Sources: `npm audit --omit=dev --json` (`npm-audit-omit-dev-2026-10-09.json`) and the OSV querybatch over all 1,138
unique lockfile package@versions (`osv-lockfile-2026-10-09.json`). The two databases agree. Upstream on 9 Oct: the
latest mysql2 is 3.24.5. prisma has no stable 7.x after 7.10.0 (dist-tags: `latest` = 8.0.0-rc.22, `prev` = 7.10.0).
8.0.0-rc.22 does not depend on mysql2; 8.1.0-dev.9 pins mysql2 3.24.4.

Version skew observed in passing: the prisma CLI is 7.10.0 while `@prisma/client` and `@prisma/adapter-pg` are
7.4.2 (`prisma --version`). This is not a vulnerability. It means the client is generated by a newer CLI than the
runtime it runs on. Record it for the lead.

## Where mysql2 is loaded: build, CLI, runtime
1. **Runtime (Vercel functions): not shipped.** The certified build's 278 `.nft.json` traces
   (`nft-trace-scan-xP9P9cHvx9xkgqHPXnOa9.json`) contain 0 files under `node_modules/mysql2/`, `node_modules/prisma/`,
   `@prisma/studio-core` or `node_modules/postgres/`. No file in `app/`, `lib/`, `components/`, `auth.ts`, `proxy.ts`,
   `instrumentation*.ts` or `next.config.ts` imports mysql2. This is now enforced by
   `scripts/readiness/supply-chain-check.mjs` and `tests/unit/sec-e-supply-chain.test.ts`.
2. **Build chain (Vercel build and local): installed, but not loaded by the commands the build runs.** The build runs
   `prisma generate` (postinstall) and `prisma migrate deploy` (`scripts/maybe-migrate.mjs`). The CLI bundle
   (`node_modules/prisma/build/cli.js`) has exactly one load site, a dynamic `import("mysql2/promise")` inside
   `mysql:{adapter:"mysql",async createExecutor(e){…}}`. That is the Prisma Studio executor for a MySQL datasource.
   Runtime proof: a module-load tracer (`load-tracer.cjs`; CJS `_resolveFilename` plus `module.registerHooks` for ESM
   and dynamic import) recorded `prisma --version`, `prisma validate` and `prisma generate`, all exit 0, with DATABASE_URL
   pointed at an unreachable dummy. **0 files from `node_modules/mysql2/` were resolved** (`prisma-cli-load-trace.jsonl`).
   The positive control, `import("mysql2/promise")` under the same tracer, recorded 150 mysql2 files
   (`prisma-cli-load-trace-positive-control.jsonl`). `@prisma/studio-core/dist/data/mysql2/index.cjs` *is* loaded at CLI
   start, but it is an adapter that receives an injected client and does not import the mysql2 package.
   `migrate deploy` was not traced: it needs a database. Its code path drives the Rust schema engine for the
   `postgresql` provider.
3. **Reachable input path for the advisories.** Both bugs need a mysql2 client to connect to an attacker-controlled
   or attacker-positioned MySQL server. Our datasource is `provider = "postgresql"`, and the only executor that loads
   mysql2 is `prisma studio` with a MySQL URL, which is never run here.

**Disposition: NOT APPLICABLE WITH EVIDENCE for runtime and for the build commands traced, still PRESENT IN THE BUILD
CHAIN.** That is different from "not applicable". The package sits on the build machine that holds production
DATABASE_URL, and npm and OSV keep reporting it. A future CLI path, or `prisma studio` against MySQL, would load it.

## Real remediation options (verified on a disposable copy, not applied)
1. **Recommended: npm override** `"overrides": { "mysql2": "^3.24.5" }` (package.json already uses `overrides`).
   Simulated in `<scratchpad>/security/E/ovr` with `npm install --package-lock-only --ignore-scripts`: mysql2 3.15.3 →
   3.24.5; denque, seq-queue and sqlstring removed; sql-escaper 1.5.2 added; iconv-lite 0.7.2 → 0.7.3; plus npm
   re-resolving six nested `@tailwindcss/oxide-wasm32-wasi` wasm helpers (dev/optional). Then
   `npm audit --omit=dev` → **0 vulnerabilities** (`mysql2-override-simulation-audit.json`). Risk: Prisma Studio's MySQL
   path runs on a mysql2 minor that Prisma did not test. This repository does not use that path. It changes
   package.json and the lockfile, so the full gates plus `npm run build` must be re-run, and the tested-build identity
   changes. That is the lead's decision.
2. Move `prisma` to devDependencies. This silences `--omit=dev` but changes nothing real: Vercel installs devDependencies
   for the build. Not recommended on its own.
3. Downgrade to prisma 6.19.3 (npm's suggestion). This breaks Prisma 7 config, the driver adapter and the query
   compiler. **Rejected.**
4. Wait for a stable prisma 8 (`8.0.0-rc.22` drops mysql2). Not yet stable.

The time-boxed exception is encoded in `supply-chain-check.mjs` (`AUDIT_EXCEPTIONS`, expires 2026-11-09). After that
date the audit gate fails again unless the override lands or the decision is renewed.
