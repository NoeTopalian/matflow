  another file that writes through a passed-in client cannot be seen by a textual guard.

## Proposed migration (lead owns prisma/schema.prisma) — database-enforced cross-table identity

A `BEFORE INSERT OR UPDATE OF "email"` trigger on "User" and "Member" that takes the same transaction-scoped advisory
lock as `claimLoginIdentity` (namespace `0x4c474944`, key = first 4 bytes of SHA-256 over `tenantId:lower(btrim(email))`,
computable in SQL with `('x'||substr(encode(sha256(convert_to(…,'UTF8')),'hex'),1,8))::bit(32)::int`) and raises
`unique_violation` when the other table holds `lower(btrim(email))` in the same tenant, skipping `@no-login.matflow.local`
and `@deleted.invalid` addresses. This closes scripts, seeds and raw SQL too. Needs a TEST-branch race run under both
roles before adoption. The check only needs rows of the SAME tenant, which RLS already lets a writer see inside its own tenant context (or under the bypass), so no SECURITY DEFINER is needed; a write made with neither setting would see nothing and must be refused by the trigger rather than passed.
