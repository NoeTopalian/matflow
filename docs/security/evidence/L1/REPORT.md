# Lane L1 (SF-135: post-burst connection failures) — cycle 1, 11 Oct 2026 (saved by the coordinator from the hand-back)

Base HEAD 2876108 (lib/ identical to 704ab57). Node v24.21.0. Nothing staged or committed by the lane; no production access, no migrations, no backend termination; no refusals.

## 1. Cause (proven)
Every unhandled rejection in L1's runs and in R9's logs shares one stack: `Timeout.<anonymous>` (Prisma 7.4.2 TransactionManager `#startTransactionTimeout`) → `#closeTransaction` → `PgTransaction.executeRaw` (the ROLLBACK) → pg `_errorAllQueries`. Sequence: a transaction outlives Prisma's own timeout (5 s batch default for checkDbRateLimit, 10 s for the reservation) while one of our statements is still in flight (queued on the bucket lock or stalled on the network); Prisma's timer can only QUEUE its ROLLBACK behind that statement, never interrupt it; when the socket then ends, pg rejects both — the statement's rejection reaches the caller (which refuses), the timer's ROLLBACK rejects inside a timer callback nothing awaits. Origin: library pool/client lifecycle interacting with our transaction timing; not teardown. Owner of the failing promise: Prisma's TransactionManager; owner of the timing: the code opening the transaction. Supporting: the TEST server has no statement or lock timeout (idle-in-transaction 5 min); the drops are on the network path (connect ETIMEDOUT / ENETUNREACH; warm-ups > 10 s seen during the lane); deterministic reproduction on the test's own pooled client — pause the socket past the old timer then close or reset it → 4 unhandled rejections per run under both roles before the fix (repro.txt §3).

## 2. Impact, each with its probe
Process termination: plain Node and vitest exit 1; Next.js 16.3.8's own handlers log `⨯ unhandledRejection` and the server keeps running (next-handler-probe, repro.txt §6); the owning request had already been decided as a refusal (its own statement rejected on the same tick). Client leak: none (dead client leaves the pool; positive control served; both roles). Misreported outcome: none for security — rate limit refused with Retry-After 30 s; reservation thrown and auth.ts refuses — but the wording is wrong: a right password reads as "incorrect" (SF-118). Lost counter: none on this path (0 rows, no verdict reached); an ambiguous COMMIT can only over-count. Weakened denial: none — every injected failure refused under both roles; mutant MD2 shows the cells catch an admission.
